从《东方年代记》游戏存档与攻略资料中**只读**整理出的个人游戏历程记录。六份可离线打开、
也可在线浏览的单文件页面。全程不修改任何游戏文件。

| 页面 | 内容 |
|---|---|
| `index.html` **称号档案** | 124 个称号，带获得日期、章节、难度（**只统计本人三份备份**） |
| `nodes.html` **旅程节点地图** | 305 个存档节点 + 304 张原生存档截图 + 章间评价（**只统计本人三份备份**） |
| `ending.html` **结局真相 · 攻略对齐** | 结局分派链 + 攻略与脚本逐条对账 + 存档拖入体检 |
| `debug.html` **调试面板与热键** | 从内存提取的 331 段脚本还原：Shift+F3 真相、F9 变量总表、作弊码与全套调试热键 |
| `variables.html` **F9 变量词典** | 游戏自己导出的 500 个变量 / 700 个开关**中文实名** + 80 条作者全局常量 + 各章评价阈值 + 10 个结局判定 + 8 个外部结局档实测对照 |
| `tools.html` **修改器 Tools 解剖** | 社区工具 `东方年代记Tools1.3` 的脱壳与静态解剖：它靠进程内存读写工作，附功能全表与和本档案的交叉验证 |

### 3.2 攻略 ↔ 脚本 逐条对账

> **基准版本：`东方年代记_攻略集Ver1.05`（本项目唯一权威攻略版本）。**
> `Ver2.0` 对应的是另一套改过数值的版本，已排除，仅在下文作对照。

1.05 把每个加分点都标了 `+N`，而事件脚本里每一次 `变量操作 : [48] += N` 就是一个真实的加分点。
**第 8 章 37 条条目全部在脚本里找到了对应指令：**

- 攻略说「在隙间之里完整搜集情报 **+10**」，脚本里 `变量[205]` 全文件**恰好 10 个写点**，
  每个房间一处，同时给 `变量[48] +1` —— **数目精确吻合**。
- 攻略的 6 台补给机写了 6 个密码（`2365 / 1687 / 2519 / 1020 / 7717 / 1379662`），
  脚本里**恰好 6 个 `变量[212] == 密码` 判定**，分布在 6 张地图上。
- 攻略的 7 个里程点 `18 → 24 → 28 → 31 → 37 → 43 → 48`，按 `+N` 顺序累加**全部精确复现**，
  终点正好是满分 48。
- 外部结局档实测：`变量[48] = 48`、`变量[205] = 10`、`变量[213]`（已破解补给机数）`= 6`，
  与上面的满分模型完全一致。

**两处自我修正（上一版的错误结论）：**

- 上一版写「击破茨木华扇 **+3**，但脚本里找不到这 3 分」——**这个 +3 是我自己算出来的**。
  1.05 在茨木华扇这一条上根本没有标 `+N`。当时的错误是：看到 `28/48 → 31/48` 差 3 分，
  就默认来自紧邻的茨木华扇，**漏看了中间还夹着「狮子王卢萨 +1」「击破艾丽 +1」「分杀玛塔 +1」**。
  茨木华扇实际是 **0 分**，修正后**根本不存在「找不到出处的 4 分」**。
- 上一版标「脚本里找不到」的「击破艾伦 +1」「流刃若火 +1」「幻夜之宵龘曌之法 +1」，
  这一版**全部找到了**（艾伦在蒙卡坦图陵墓 ev3；后两个在白玉楼部屋与永远亭部屋，
  上一版搜错了事件页）。

## 四、F9 变量词典（variables.html）

调试模式（合成界面输入 `mikomikomomoko`）下按 `F9` 打开的 RMXP 标准调试画面 `Scene_Debug`，
左栏是 `S [0001-0010]` … `V [0001-0010]` … 的区块目录，右栏是这 10 个的具体值。
本作是 **700 个开关 / 500 个变量**。本页回答「这些格子里，哪些有用」。

**数据来源（四层，互相印证）**

1. ★ **游戏自己导出的实名表**（2026-09-20 新增，最硬的一层）——
   `_dump_variables.txt`（500 格，313 个有名字）、`_dump_switches.txt`（700 格，603 个有名字）、
   `_dump_globals.txt`（80 条作者全局常量）。走的是作者自留的 `script.txt` + `F10` 通道，全程只读。
2. **作者写死在脚本里的编号常量** —— 57 条，注释就是用途。
   例：`ROUND_VARIABLE = 9`、`GAME_END_VARIABLE = 400`、`GAME_END_SWITCH = 455`、
   `$流程变量编号 = 25`、`$森罗章节开关编号 = 260`、`$第⑨章节开关编号 = 635`、
   `LEVEL_UP_VARIABLE = 300`（角色点数 = `V[300 + 角色id]`）。
3. **`o0287` 的章节评价表** —— 每章一个评价变量（`V[41]–V[50]` 与间章 `V[76]–V[81]`），
   以及 S/A/B 三档阈值；评价值 `≤ 0` 该章直接判 D。同时给出「流程变量到多少 = 第几章」的完整对照。
4. **`var_index.json`** —— 对游戏自己导出的 833 907 行事件文本做全文索引，
   统计出 **204 个变量 / 460 个开关**的读写次数、出现地图、典型赋值与典型判断。

**实名表纠正/补出的几件事**

- `V[49]` 其实是「森罗佣兵贡献度」，第九章的评价格是 `V[50]`「第九章S评价」。
- `S[214]` 是「★停止刷新开关」、`S[221]` 是「★一方通行」——
  此前被误记成「菜单」和「商人」，实名表一到就直接纠正。
- **补出 `S[225]`「★前往新世界」**：第八章的选项是**两格互斥的开关**
  （`S[224]` 守护幻想乡 / `S[225]` 前往新世界），此前只用了一格。
- 据此更正了结局判定链（见 3.1 / 3.1.1），并用 8 个外部结局档重跑回归测试：**7/7 通过**。

**现场导出方法（可重复）**

调试模式下按 `F10`，会执行游戏目录里的 `script.txt`，生成
`_dump_variables.txt` / `_dump_switches.txt` / `_dump_party.txt` / `_dump_globals.txt` / `_dump_done.txt`。
纯 ASCII、只新建文件、不写存档。
⚠️ `F10` **只读取并执行** `script.txt`，**永远不会写它** —— 所以 `script.txt` 的修改时间变化
一定来自人工编辑（本次就是），判断游戏是否真的跑过导出，要看 `_dump_done.txt` 里的时间戳。

## 五、修改器 Tools 解剖（tools.html）

对社区流传的 `东方年代记Tools1.3\TH Tools.exe` 做**脱壳 + 静态分析**（全程只读，未运行该程序）。

**它是什么**：UPX 加壳的**易语言**程序（界面用 Exui 皮肤库），脱壳后 3.25 MB → 6.27 MB，
PE 编译时间戳 2024-05-22。目录里的 `ExuiKrnln_Win32.lib` 是作者打包时忘删的编译期导入库，
运行不需要它。

**它怎么工作**：**进程内存读写**。脱壳后 `.rdata` 里有一整段连续的 API 名字表：

```
OpenProcess · ReadProcessMemory · WriteProcessMemory · VirtualProtectEx
VirtualAllocEx · CreateRemoteThread · CreateToolhelp32Snapshot
Process32First/Next · Module32First/Next · Thread32First/Next
ZwOpenProcess · ZwQuerySystemInformation · ZwDuplicateObject
ZwWow64ReadVirtualMemory64 · ZwWow64WriteVirtualMemory64
```

找到 `Game.exe` → 打开 → 直接读写它的内存。**不碰存档、不联网、不注入 DLL。**
（全文件搜不到 `socket`/`connect`/`send`/`recv`/`WSAStartup`、搜不到 `13666` 与任何 IP；
全文件扫描内嵌 `MZ`/`PE` 头 **0 个**。）关掉游戏，它做的一切就消失。

**主界面**：标题 `东方年代记Tools #未检测到进程 请选择您的游戏版本：`，
版本下拉含 `1.00` `1.05` `2.02` `2.05` `2.06` `4.02` `Bart0.1-1.11` `Bart1.12-1.14`
——说明它是**按版本查表**工作的。

**功能**（基础功能 / 其他功能 / 物品获取 / 地图传送 四区）：
无限金币 · 一键秒杀（两档）· 购买出售数量锁定 99 · 无限潜能点 · 人物满级 ·
幽灵船/鬼屋/补船洞立即结束 · 人物跟随 · 高级暂停 · 测试模式 · 连击数 99999 ·
各章评价点与章间评价点修改 · 游戏流程/周目/森罗贡献度/加点点数 ·
不显示各种得失 · 称号直接显示 · 取消方向颠倒/地震/黑暗 · 升空宝箱无限开 ·
进入森罗界面 · 启动简单/挑战模式 · 双姬潜能全开 · 一等奖开关 · 露米娅停止追逐 ·
十种合体技能开关 · 反神将开关 · 队伍编成开关 · 物品获取（**仅限 2.0 以上版本**）· 地图传送。

**交叉验证（意外收获）**：把工具里的开关标签和本档案的实名表一对，**全部命中**
（一等奖开关=`S[203]`、队伍编成开关=`S[215]`、反神将=`S[216]`、
天人五衰…月兔集中=`S[241]`–`S[249]`、森罗界面=`S[590]`）。
更关键的是它的"评价点"满分表与我们的结论完全一致，**独立确认了三件事**：

1. 间章**只有 6 格**（二·三·四·五·六·八），**没有「第七章间章」**；
2. 间章满分 5+11+18+21+19+35 = **109**，主章满分 15+16+28+35+62+25+28+48 = **257**；
3. **257 + 109 = 366** —— 真结局「涅槃朝霭的幻想乡」的点数门槛。

**风险提示**：它含 `WriteProcessMemory` + `VirtualAllocEx` + `CreateRemoteThread` +
`SetWindowsHookEx` + UPX 壳，行为特征与木马同构，被安全软件拦下属正常。
它只改内存，因此**「用完正常存档就会把改后的数值写进档」**，
工具自己也标注了「人物满级（进战斗前关闭/存档前关闭）」。
若只是想体验剧情，**优先用游戏内置的 `F9` 面板 / `F11` 控制板 / `Ctrl` 穿墙**，风险更低。
