# 东方年代记 · 我的十年旅程档案

从《东方年代记》游戏存档与攻略资料中**只读**整理出的个人游戏历程记录。三份可离线打开、
也可在线浏览的单文件页面。全程不修改任何游戏文件。

| 页面 | 内容 |
|---|---|
| `index.html` **称号档案** | 225 个称号，带获得日期、章节、难度 |
| `nodes.html` **旅程节点地图** | 316 个存档节点 + 307 张原生存档截图 + 章间评价 |
| `ending.html` **结局真相 · 攻略对齐** | 真实结局分派链 + 攻略与脚本逐条对账 + 存档拖入体检 |

## 三、结局真相 · 攻略对齐（ending.html）

这一页做了三件事。

### 3.1 结局分派链（经 8 个真实结局档交叉验证）

```
第 8 章末 · 魔煌之池（打完神绮）
├─ 开关[445] ON  （爱丽丝入队 ← 队里有魔理沙救下她）→ 秘义之境 → 继续分派
└─ 开关[445] off
     ├─ 开关[414] ON  （隙间之里情报 ≥ 10）→ 「残缺的世界」
     └─ 开关[414] off                      → 「毁灭的蓬莱物语」

幻想乡之境 · EV003   ※ RMXP 规则：条件成立的「页码最大」的那一页生效
├─ 第 3 页 · 开关[223] ON（妹红辉夜未曾离队）→ 「平静依然的乐土」
└─ 第 2 页
     ├─ 开关[224] ON（「至死不渝守护我们幻想乡」）→ 「辉光指引的幻想乡」★ TRUE END
     └─ 开关[265] ON（救出梅蒂馨）               → 「新的未来」
```

六个决定性开关：**258**（与梅莉·莲子相遇，最早的一个岔口）、**223**、**445**、**414**、**224**、**265**。
其余 600 多个开关只是剧情进度标记。

**验证结果**：把 8 个结局档的开关状态代进上面这张图，6 个可验证的结局全部吻合
（森罗线是独立路线，不参与分派）。

### 3.2 攻略 ↔ 脚本 逐条对账

> **基准版本：`东方年代记_攻略集Ver1.05`（本项目唯一权威攻略版本）。**
> `Ver2.0` 对应的是另一套改过数值的版本，已排除，仅在下文作对照。

1.05 把每个加分点都标了 `+N`，而事件脚本里每一次 `变量操作 : [48] += N` 就是一个真实的加分点。
**第 8 章 37 条条目全部在脚本里找到了对应指令：**

- 攻略说「在隙间之里完整搜集情报 **+10**」，脚本里 `变量[205]` 全文件**恰好 10 个写点**，
  每个房间一处，同时给 `变量[48] +1` —— **数目精确吻合**。
- 攻略的 6 台补给机写了 6 个密码（`2365 / 1687 / 2519 / 1020 / 7717 / 1379662`），
  脚本里**恰好 6 个 `变量[212] == 密码` 判定**，分布在 6 张地图上。
- 攻略的 7 个里程点 `18 → 24 → 28 → 31 → 37 → 43 → 48`，按 `+N` 顺序累加**全部精确复现**，
  终点正好是满分 48。
- 真实真结局档实测：`变量[48] = 48`、`变量[205] = 10`、`变量[213]`（已破解补给机数）`= 6`，
  与上面的满分模型完全一致。

**两处自我修正（上一版的错误结论）：**

- 上一版写「击破茨木华扇 **+3**，但脚本里找不到这 3 分」——**这个 +3 是我自己算出来的**。
  1.05 在茨木华扇这一条上根本没有标 `+N`。当时的错误是：看到 `28/48 → 31/48` 差 3 分，
  就默认来自紧邻的茨木华扇，**漏看了中间还夹着「狮子王卢萨 +1」「击破艾丽 +1」「分杀玛塔 +1」**。
  茨木华扇实际是 **0 分**，修正后**根本不存在「找不到出处的 4 分」**。
- 上一版标「脚本里找不到」的「击破艾伦 +1」「流刃若火 +1」「幻夜之宵龘曌之法 +1」，
  这一版**全部找到了**（艾伦在蒙卡坦图陵墓 ev3；后两个在白玉楼部屋与永远亭部屋，
  上一版搜错了事件页）。

### 3.4 存档体检

把任意 `.rxdata` 拖进页面，浏览器内本地解析（内置自写的 Ruby 1.8 Marshal 解析器，纯 JS），
按上面那张真实分派链给出结局预判，并列出六个关键开关、八章评价条与进度变量。**文件不上传。**

### 3.5 为什么以 Ver1.05 为准（可验证的事实，不是偏好）

把两版的补给机密码拿去 833,896 行的事件脚本里搜：

| 攻略密码 | 脚本里的判定 | 脚本中命中 |
|---|---|---|
| `2365` | `变量[212] == 2365` | 2 |
| `1687` | `变量[212] == 1687` | 2 |
| `2519` | `变量[212] == 2519` | 2 |
| `1020` | `变量[212] == 1020` | 2 |
| `7717` | `变量[212] == 7717` | 2 |
| `1379662` | `变量[212] == 1379662` | 2 |
| `8230` / `11110000` / `9236` / `6715`（2.0 的写法） | 未找到 | **0** |

其余对不上的地方：

- 第 3 章暗号：1.05 写 `[32489]`（脚本里出现 6 次），2.0 写成「随机」。
- 第 8 章幻想酒吧 NPC：1.05 写 **米斯提亚**，2.0 改成「小碎骨」。
- 第 7 章：1.05 要求补 **30** 个漏洞、以 **5 残以上** HP 躲幽灵船、**40 回合内**击破灵梦；
  2.0 改成 40 个漏洞、15 残、不写回合数。
- 第 4 章：1.05 是「完美避开所有警卫」（零容错），2.0 放宽成「允许发现一次」。

**结论：1.05 的数值就是本游戏的数值；2.0 是另一套把数值与容错都调整过的版本，
它「更详细」说明不了任何问题。**

两版文字都是 GBK 编码，但 `<meta>` 标成了 utf-8 —— 按 utf-8 读会全变乱码。

## 已知局限

- **称号图标缺失**：原始记录中的 `@pic` 指向 `TitleRewards\tr*`，
  这些资源全部打包在加密容器 `thndj.mpq`（319 MB）内，无法读取。
  因此称号页用「章节归属 + 难度着色」代替原版图标。
- **未记录称号只有 ID、没有名字**：原因同上。
- **「重逢，再次开始的旅程」与「消失的蓬莱传说」的路由未完全查清**：
  这与开关组合近乎相同的「新的未来」区分不开，区别落在剧情进度变量 `[25]`
  （195 vs 225）上。页面对这两条已明确标注「推断」。
- ~~4 分的加分区来源未定位~~ —— **已解决**：那 4 分是我上一版的算术错误造出来的，
  实际不存在缺口（见 3.2 的自我修正）。
- **游戏内补丁不可行**：`Game.ini` 声明 `Scripts=Data\Scripts.rxdata`，但磁盘上没有 `Data` 目录；
  数据全在 `thndj.mpq` 与 `Patch/10501/*.mpq` 中，且容器内无任何明文文件名。
  `RGSS102J.dll` 在游戏目录与系统内均不存在，没有可劫持的代理 DLL 落点。
  （附带查清：`RGSSNDJ.dll` 其实不是 DLL，而是 1196 字节的 Marshal 数据文件，
  内容是初始队伍模板。）

## 生成方式

读取存档用的是自写的 Ruby 1.8 Marshal 解析器（RPG Maker XP / RGSS102J 格式），
支持 RMXP 存档里**多段连续 Marshal 流**的结构。结局条件与加固逻辑全部来自
`all_map_events.txt` 的指令级导出，并用 8 个真实结局档做了回归测试
（`ending.html` 的判定函数 7/7 通过）。全程只读，不修改任何游戏文件。
