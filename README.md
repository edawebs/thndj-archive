# 东方年代记 · 我的十年旅程档案

从《东方年代记》游戏存档与攻略资料中**只读**整理出的个人游戏历程记录。三份可离线打开、
也可在线浏览的单文件页面。全程不修改任何游戏文件。

| 页面 | 内容 |
|---|---|
| `index.html` **称号档案** | 225 个称号，带获得日期、章节、难度 |
| `nodes.html` **旅程节点地图** | 316 个存档节点 + 307 张原生存档截图 + 章间评价 |
| `ending.html` **结局真相 · 攻略对齐** | 真实结局分派链 + 攻略与脚本逐条对账 + 存档拖入体检 |

## 三、结局真相 · 攻略对齐（ending.html）

这一页做了三件事。

### 3.1 结局分派链（经 8 个真实结局档交叉验证）

```
第 8 章末 · 魔煌之池（打完神绮）
├─ 开关[445] ON  （爱丽丝入队 ← 队里有魔理沙救下她）→ 秘义之境 → 继续分派
└─ 开关[445] off
     ├─ 开关[414] ON  （隙间之里情报 ≥ 10）→ 「残缺的世界」
     └─ 开关[414] off                      → 「毁灭的蓬莱物语」

幻想乡之境 · EV003   ※ RMXP 规则：条件成立的「页码最大」的那一页生效
├─ 第 3 页 · 开关[223] ON（妹红辉夜未曾离队）→ 「平静依然的乐土」
└─ 第 2 页
     ├─ 开关[224] ON（「至死不渝守护我们幻想乡」）→ 「辉光指引的幻想乡」★ TRUE END
     └─ 开关[265] ON（救出梅蒂馨）               → 「新的未来」
```

六个决定性开关：**258**（与梅莉·莲子相遇，最早的一个岔口）、**223**、**445**、**414**、**224**、**265**。
其余 600 多个开关只是剧情进度标记。

**验证结果**：把 8 个结局档的开关状态代进上面这张图，6 个可验证的结局全部吻合
（森罗线是独立路线，不参与分派）。

### 3.2 攻略 ↔ 脚本 逐条对账

作者攻略 `东方年代记_攻略集Ver2.0` 把每个加分点都标了 `+N`，
而事件脚本里每一次 `变量操作 : [48] += N` 就是一个真实的加分点。对账结果：

- 攻略说「在隙间之里完整搜集情报 **+10**」，脚本里正好有 **10 处** 房间情报点，
  每处同时给 `变量[205] +1` 和 `变量[48] +1` —— **数目精确吻合**。
- 攻略的四个里程点 `18/48 → 24/48 → 31/48 → 37/48`，按 `+N` 顺序累加，
  **18、24、37 三个完全复现**。
- 抽查 5 处（击破灵梦 +2、击破艾伦 +1、救出梅蒂馨 +1、玫瑰补救露米亚 +2、击破魅魔 +2）**全部命中**。
- **4 分找不到出处**：「击破茨木华扇」（攻略记 +3）与「击破艾伦」（+1）的战斗胜利分支里
  没有 `变量[48]` 加分指令。推测由**公共事件**给分 —— `all_map_events.txt` 只导出地图事件，
  没导出公共事件，那部分在加密的 `thndj.mpq` 里。**这是推断，不是结论。**
  这 4 分只影响评价奖励档位，不影响结局。

### 3.4 存档体检

把任意 `.rxdata` 拖进页面，浏览器内本地解析（内置自写的 Ruby 1.8 Marshal 解析器，纯 JS），
按上面那张真实分派链给出结局预判，并列出六个关键开关、八章评价条与进度变量。**文件不上传。**

### 3.5 两版攻略集的关系

`Ver2.0` 的第 5–8 章正文明显更长（第 5 章 6,709 字 vs 4,858 字），
且第 8 章**直接写明了三个结局条件**。两版文字都是 GBK 编码，但 `<meta>` 标成了 utf-8 ——
按 utf-8 读会全变乱码。

## 已知局限

- **称号图标缺失**：原始记录中的 `@pic` 指向 `TitleRewards\tr*`，
  这些资源全部打包在加密容器 `thndj.mpq`（319 MB）内，无法读取。
  因此称号页用「章节归属 + 难度着色」代替原版图标。
- **未记录称号只有 ID、没有名字**：原因同上。
- **「重逢，再次开始的旅程」与「消失的蓬莱传说」的路由未完全查清**：
  这与开关组合近乎相同的「新的未来」区分不开，区别落在剧情进度变量 `[25]`
  （195 vs 225）上。页面对这两条已明确标注「推断」。
- **4 分的加分区来源未定位**：见 3.2。
- **游戏内补丁不可行**：`Game.ini` 声明 `Scripts=Data\Scripts.rxdata`，但磁盘上没有 `Data` 目录；
  数据全在 `thndj.mpq` 与 `Patch/10501/*.mpq` 中，且容器内无任何明文文件名。
  `RGSS102J.dll` 在游戏目录与系统内均不存在，没有可劫持的代理 DLL 落点。
  （附带查清：`RGSSNDJ.dll` 其实不是 DLL，而是 1196 字节的 Marshal 数据文件，
  内容是初始队伍模板。）

## 生成方式

读取存档用的是自写的 Ruby 1.8 Marshal 解析器（RPG Maker XP / RGSS102J 格式），
支持 RMXP 存档里**多段连续 Marshal 流**的结构。结局条件与加固逻辑全部来自
`all_map_events.txt` 的指令级导出，并用 8 个真实结局档做了回归测试
（`ending.html` 的判定函数 7/7 通过）。全程只读，不修改任何游戏文件。
