东方年代记 Tools 1.3 · 它是怎么运作的

社区流传的「TH Tools」。结论先说：它不是存档编辑器，也不是联网工具—— 它是一个标准的进程内存读写器（俗称修改器／外挂），在游戏运行时直接读写 Game.exe 的内存。本页把它拆开：加壳、脱壳、API 名单、功能表、 以及它和我们这套档案的交叉验证结果。

一句话结论

它靠 OpenProcess + ReadProcessMemory / WriteProcessMemory 直接改运行中的游戏内存。不碰存档文件、不发网络包、不注入 DLL（脱壳后全文件扫描 MZ/PE 头，内嵌 PE 0 个）。

换句话说：它做的事和游戏内置的 F9 面板原理完全一样（改内存里的开关/变量）， 只是把它包成了图形界面，再额外加了一批「一键」操作（秒杀、满级、传送……）。

关掉游戏，它做的一切就没了——这也是它和「改存档」最大的区别。

一 · 它由什么组成

目录 东方年代记Tools1.3\ 里只有三样东西：

文件大小是什么
TH Tools.exe3 248 640 B主程序。UPX 加壳的易语言程序，界面用 Exui 皮肤库
ExuiKrnln_Win32.lib1 795 072 BExui 皮肤库的编译期导入库——作者打包时忘删的残留文件，运行不需要它
Tools使用说明.txt231 B三行提示：管理员运行 / 别开搜狗输入法 / 勾选右下角滑动按钮
三条使用说明，逐条都能解释

· 「请勾选以管理员身份运行」 —— 修改器要 OpenProcess 别的进程并 WriteProcessMemory，这类权限在普通用户态下容易被拦；提权后更省事。
· 「请勿打开搜狗输入法」 —— 工具自己装了全局键盘钩子（导入表里有 SetWindowsHookExA），输入法也做钩子，两者会抢。
· 「获取到游戏数据请勾选右下角的滑动按钮，防止游戏崩溃」 —— 它先扫描定位、 再把地址锁住持续读写；不锁住的话游戏重新分配内存，读写就会打到野地址上崩掉。

二 · 怎么看出来是内存修改器（脱壳过程）

原始 exe 是加壳的：节表里只有 UPX0 / UPX1 两个节， UPX0 的磁盘大小是 0——典型 UPX 特征。用 UPX 4.2.4 -d 还原后 3.25 MB → 6.27 MB，节表恢复正常（.text / .rdata / .data / .rsrc）。

脱壳后，在 .rdata 的 0xECA23–0xED112 有一整段 连续的 API 名字表（易语言调用外部 API 的方式是把名字以字符串形式存着）——这就是铁证：

; 0x000ECD35 起，按顺序
OpenProcess      VirtualAllocEx    WriteProcessMemory   CreateRemoteThread
CreateToolhelp32Snapshot              Process32First       Process32Next
Module32First    Module32Next      Thread32First        Thread32Next
VirtualQueryEx   VirtualProtectEx  VirtualFreeEx        GetModuleInformation
OpenProcess      ZwOpenProcess     ZwQuerySystemInformation  ZwDuplicateObject
ZwQueryInformationProcess             ZwClose
ReadProcessMemory ×N                  WriteProcessMemory ×N
ZwWow64ReadVirtualMemory64            ZwWow64WriteVirtualMemory64
GetCurrentProcessId  IsBadReadPtr  IsBadWritePtr ...

这串东西合起来只有一种用途：枚举进程 → 打开目标 → 扫描/读取/写入它的内存。 另外还有 FFD6（call esi）、83C4 / 81C4 （add esp, ...）这类**汇编片段模板**，说明这个模块具备「在目标进程里搭一小段 代码去调用 API」的能力（远程调用），不过是否真的用到，我无法静态确证。

它没有联网。虽然导入了 WS2_32.dll，但里面没有 socket / connect / send / recv / WSAStartup ——只有易语言运行时默认会挂上的几个序号函数。所以它不走游戏那个 TCP 13666 调试通道。 （ShellExecuteA 只用来点「点击加群」打开 QQ 群链接。）

三 · 主界面长什么样（从字符串还原）

标题栏写的是：东方年代记Tools   #未检测到进程   请选择您的游戏版本：。 「请选择您的游戏版本」下面是一个下拉框，可选项有：

1.00 1.05 · 2.02 2.05 2.06 · 4.02 · Bart0.1-1.11 Bart1.12-1.14 （另有 1.00-1.05 这样的区间写法）

这个下拉框本身就是答案：它说明工具是按版本查表工作的——同一个数据在不同版本里 位置不同，所以必须告诉它「你玩的是哪版」。工具内部要找的进程名是 Game.exe， 找不到就显示 #未检测到进程。

其它界面原文：点我重新获取数据 · 锁定速度 · 变速数值 · 点击加群 · 点击图标可查看潜能描述 · exui默认窗口皮肤。

更有价值的：它替我们确认了「满分表」

工具的「评价点修改」把每个章节的满分直接写在界面上，和我们之前从脚本里推出、 又被 8 个真实结局档验证过的数值完全一致：

主章一二三四五六七八合计
Tools 界面1516283562252848257
间章二三四五六七八—合计
Tools 界面511182119没有35—109
三点独立确认：
① 间章只有 6 格（二·三·四·五·六·八），没有「第七章间章」——与我们从实名表得到的一致；
② 间章满分合计 = 5+11+18+21+19+35 = 109；主章满分 = 257；
③ 于是 257 + 109 = 366 —— 这正是真结局「涅槃朝霭的幻想乡」所需的点数门槛。 这份外部工具等于替 366 这个数字背了一次书。

五 · 局限与风险（说清楚）

1.05 上它能做什么、不能做什么

能：金币、秒杀、满级、潜能点、评价点、流程/周目/贡献度、各类开关、地图传送、变速、暂停。
不能：「物品获取」在 1.05 上不可用（界面自己标了「仅限 2.0 以上版本使用」）； 「瓦尔哈拉 / 第四法」这类内置控制板功能它没有——那些要靠游戏自己的 F11。

2. 为什么杀软会报它

文件里明摆着 WriteProcessMemory + VirtualAllocEx + CreateRemoteThread + SetWindowsHookEx 这一套组合， 再加一层 UPX 壳——这正是木马最常用的技术栈。 它本身没有联网、没有内嵌 PE、没碰注册表以外的持久化， 但「行为特征像木马」这件事无法避免，所以被杀软拦下是正常现象。

3. 用它之后存档还能要吗

能，但要小心用。它只改内存，所以：
· 用完在游戏里正常存档 → 存档里就带上改后的数值；不存档直接退 → 一切恢复；
· 工具自己就写了警告：人物满级（进战斗前关闭/存档前关闭） —— 满级状态存进档里会出问题，用完必须关掉再存。
· 「一键秒杀」同理，别在战斗结算前开着，否则可能把剧情判定跳坏。

和内置 F11 控制板比，谁更安全？ 内置的不依赖外部程序、也不越权， 风险更低；Tools 的优势只是「更省事、能改评价点、能传送」。 如果只是想体验剧情，优先用游戏自带的东西（F9 面板 / F11 控制板 / Ctrl 穿墙）。

六 · 一句话总结

它是什么：一个 UPX 加壳的易语言程序，用 Exui 做界面，靠枚举进程找到 Game.exe，再用 ReadProcessMemory / WriteProcessMemory 直接改运行中的游戏内存。

它不是什么：不是存档编辑器（全文件无 .rxdata 相关串）、 不是联网工具（全文件无 socket 调用、无地址、无 13666）、不注入 DLL（全文件无内嵌 PE）、 不需要先开游戏内置调试模式（它直接改内存，而不是走游戏的调试界面， 所以不用先输 mikomikomomoko）。

它的价值（对这套档案）：意外成为第三方旁证—— 它独立确认了「间章只有 6 格、没有第七章间章」「间章满分 109、主章满分 257、 合计 366 = 真结局门槛」。
